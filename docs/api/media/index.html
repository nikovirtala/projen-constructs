    @nikovirtala/projen-constructs

    @nikovirtala/projen-constructs

    Opinionated projen project types that scaffold TypeScript, JSII and AWS CDK repositories with one shared config.

    Why this exists

    Projen gives you code-first project configuration, but wiring up a consistent setup across many TypeScript, JSII and AWS CDK repositories still means repeating the same choices. This library packages those choices into ready-made project types and reusable components, so every repository you generate shares the same package manager, Node.js and TypeScript versions, testing, linting and release tooling.

    It is for anyone in the projen and AWS CDK community who maintains more than one repository and wants them to behave the same way without hand-copying configuration between them.

    When not to use this

    Reach for plain projen instead when:

    • you want unopinionated projen defaults and prefer to make each tooling choice yourself
    • your setup is not pnpm-based or cannot run Node.js 26
    • you build in languages beyond TypeScript, JSII and AWS CDK

    Status and supported versions

    Stability: stable. This library requires projen ^0.104.23, pnpm 12, and Node.js >= 26.13.0. These values are maintained in src/versions.json and the project configuration; the numbers quoted across this documentation track those sources.

    Quick start

    Install the library alongside its projen and constructs peers:

    pnpm add -D @nikovirtala/projen-constructs projen constructs

    Create a .projenrc.ts that defines an AWS CDK construct library and synthesizes it:

    import { AwsCdkConstructLibraryProject } from "@nikovirtala/projen-constructs";

    const project = new AwsCdkConstructLibraryProject({
      name: "my-cdk-construct",
      author: "Your Name",
      authorAddress: "you@example.com",
      repositoryUrl: "https://github.com/your-org/my-cdk-construct.git",
      cdkVersion: "2.275.0",
    });

    project.synth();

    Then run synthesis:

    pnpm dlx projen

    Expected output: projen reads .projenrc.ts and writes the generated project files into the working directory: package.json, tsconfig.json, pnpm-workspace.yaml, the GitHub Actions workflows, the Vitest and Biome configuration, mise.toml, and the source and test scaffolding for your construct library. Re-running the command after you edit .projenrc.ts updates those files in place.

    To start a project from scratch without writing .projenrc.ts yourself:

    pnpm dlx projen new --from @nikovirtala/projen-constructs aws_cdk_construct_library

    Features

    • Standard configuration: opinionated defaults for author, release branch, package manager, Node.js, TypeScript, and tooling
    • Automatic project type discovery: generates the ProjectType enum from projen's JSII manifest (21 project types)
    • Component system: reusable components (Vitest, TypeDoc, Mise, Homebrew, Colima, LocalStack, Lambda bundling)
    • Code generation: ProjectGenerator creates project classes with standard configuration
    • ES modules: TypeScript and CDK app projects use ES modules (JSII uses CommonJS)
    • Code quality: Biome for formatting and linting
    • Testing: Vitest with coverage
    • Auto-merge: enabled with auto-approve
    • VSCode: recommended extensions and settings
    • mise: Node version management

    Usage

    Each project type applies the standard configuration and the shared components. See Configuration for the defaults and how to override them, and Components for the component reference.

    AWS CDK construct library project

    import { AwsCdkConstructLibraryProject } from "@nikovirtala/projen-constructs";

    const project = new AwsCdkConstructLibraryProject({
      name: "my-cdk-construct",
      author: "Your Name",
      authorAddress: "you@example.com",
      repositoryUrl: "https://github.com/nikovirtala/my-cdk-construct.git",
      cdkVersion: "2.275.0",
    });

    project.synth();

    AWS CDK TypeScript app project

    import { AwsCdkTypeScriptAppProject } from "@nikovirtala/projen-constructs";

    const project = new AwsCdkTypeScriptAppProject({
      name: "my-cdk-app",
      repository: "https://github.com/nikovirtala/my-cdk-app.git",
      cdkVersion: "2.275.0",
    });

    project.synth();

    JSII project

    import { JsiiProject } from "@nikovirtala/projen-constructs";

    const project = new JsiiProject({
      name: "my-jsii-project",

    import { TypeScriptProject } from "@nikovirtala/projen-constructs";
